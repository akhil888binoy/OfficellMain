# Production deployment

1. Host the frontend and API over HTTPS. Prefer sibling subdomains under one domain, such as `app.example.com` and `api.example.com`. Set the API `FRONTEND_URL` to the exact frontend origin and `REDIRECT_URI` to the registered LinkedIn callback. Set the frontend `VITE_API` to `https://api.example.com/v1` at build time.
2. Set the server variables listed in `officellserver/.env.example` in the hosting platform. Use separate production credentials and a strong random `SECRET_KEY`. Do not commit real `.env` files. `COOKIE_SAME_SITE=lax` is suitable for sibling subdomains. If the frontend and API are on different sites, set `COOKIE_SAME_SITE=none`; this requires HTTPS and may still be blocked by browsers that block third-party cookies, so same-site hosting is preferred. `DOMAIN` is optional; leave it unset for host-only cookies.
3. Build the server with `npm ci && npx prisma generate && npm run build`; apply migrations with `npx prisma migrate deploy`; start it with `npm start`. Build the frontend with `npm ci && npm run build`. The server fails startup in production when required variables are missing or frontend OAuth origins are not HTTPS.
4. Keep the API behind a trusted reverse proxy. The app trusts one proxy hop for the client IP used by rate limits and location. If that does not match the hosting topology, adjust the Express `trust proxy` setting before launch. Configure a Redis instance for shared rate limits across API instances; the local fallback is only per process.
5. Before opening access, test LinkedIn sign-in, session refresh, logout, adding a company, publishing text/photos/video, commenting, voting, and location search against the deployed frontend and API. Run `npm run test:privacy` in `officellserver` and `npm run build` in `officellclient`. Confirm database backup and restore with the hosting provider.

Uploaded photos are re-encoded. Videos use a Cloudinary incoming transformation to strip global metadata. A video can still identify a person through its visible or audible content.
